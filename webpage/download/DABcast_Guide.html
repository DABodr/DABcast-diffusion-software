User Guide
DABcast
Source-available DAB+ Broadcast Management Software
Version 1.3.12 — November 2026
A web-based control interface for the complete ODR-mmbTools chain — audio encoding, metadata, multiplexing and RF output — from a single browser window, on any device.

Overview

DABcast is a Node.js web application that orchestrates the full ODR-mmbTools process chain to produce and broadcast a DAB+ digital radio multiplex. It is designed to run on a dedicated Linux server or a Raspberry Pi 4/5, and is accessed from any browser on the local network.

Source-available
DABcast is free to use, modify and redistribute. Source code is available at github.com/DABodr/DABcast-diffusion-software.

Key Features

Feature Description
Full ODR integration Manages odr-audioenc, odr-padenc, odr-dabmux and odr-dabmod in a coordinated process chain.
Audio-based failover Detects stream failures via audio probing (not just HTTP checks). Automatically switches to a backup stream and returns to main when audio is restored.
Mux input monitoring Reads the input buffer statistics of odr-dabmux (underruns, overruns, silence, no data) for every service while ON AIR, revealing dropouts even when the encoder process is still running.
Telegram notifications Forwards logs and critical broadcast alerts to a Telegram bot, with configurable severity, silent delivery and a built-in connection test.
Live metadata — DLS & SLS Pushes Now Playing text and album art to listeners in real time. Supports direct stream metadata, JSON API polling and DL+ tags.
Raspberry Pi ready Runs on amd64 servers and Raspberry Pi 4/5 (arm64). Ships as a self-contained .deb package — no separate Node.js installation required.
Browser-based UI Clean dark-themed interface accessible from any device on your local network. No desktop environment required on the broadcast server.
Integrated secure sign-in Uses a responsive DABcast login screen, signed private sessions, login rate limiting and automatic invalidation after credential changes.
Preset management Save and restore complete multiplex configurations as JSON presets. Import/export individual services or full configurations.
Transmission modes EASYDAB (network output), EDI, HackRF and USRP1 RF output modes.

ODR Process Chain

DABcast manages the following ODR-mmbTools process chain:

odr-audioenc × N  ──ZMQ──► odr-dabmux ──EDI──► [odr-dabmod ──► hackrf_transfer]
odr-padenc × N   ──FIFO──► odr-audioenc

Each radio service (programme) runs its own odr-audioenc and odr-padenc instance. All audio streams are fed into a single odr-dabmux instance. In HACKRF or USRP1 mode, odr-dabmod generates the RF signal.

System Requirements

Hardware

  • PC / Server: any amd64 / x86-64 machine running Linux
  • Raspberry Pi: Raspberry Pi 4 or 5, 64-bit OS (arm64/aarch64)
  • Minimum 2 GB RAM recommended (4 GB for multi-service mux on Pi)
  • Stable internet connection for stream input sources

Software

  • OS: Debian 11/12 or Ubuntu 22.04/24.04 (or compatible)
  • ODR-mmbTools: odr-audioenc, odr-padenc, odr-dabmux (and odr-dabmod for RF output)
  • Optional: HackRF tools for RF transmission, ImageMagick for SLS slide processing
Important
The ODR-mmbTools must be installed before DABcast. Use the provided install-tools.sh script to install all required dependencies automatically.

Installation

Step 1 — Install ODR-mmbTools and dependencies

Run the provided script as root (or with sudo). It will install all required tools:

sudo bash install-tools.sh

The script installs: odr-audioenc, odr-padenc, odr-dabmux, odr-dabmod (optional), dablin, imagemagick, and required libraries.

Step 2 — Install the DABcast package

On x86-64 / amd64 (PC, server)

sudo dpkg -i dabcast_1.3.12_amd64.deb

On Raspberry Pi (arm64)

sudo dpkg -i dabcast_1.3.12_arm64.deb

Step 3 — Enable and start the service

sudo systemctl enable --now dabcast

Step 4 — Access the web interface

Open a browser on any device on the same local network:

http://<server-ip>:9090

DABcast displays its own secure sign-in page. The default login is admin / dabcast. Change the password immediately on first login — the interface will prompt you to do so. You can keep a trusted device signed in, and use the account panel to sign out or change credentials later.

Finding the server IP
Run hostname -I on the server to get its IP address. Example: http://192.168.1.50:9090

First Configuration

Multiplex Settings

Go to the Settings panel to configure your multiplex:

  • Ensemble name: the DAB+ ensemble label broadcast to receivers
  • EID: Ensemble Identifier (hex, e.g. 0x1001)
  • Frequency: transmit frequency in MHz (for HACKRF/USRP mode)
  • Output mode: EASYDAB, EDI, HACKRF, or USRP1
  • Gain: RF output gain (HACKRF mode)

Adding a Service (Radio Programme)

Click Add Service to configure a radio programme:

Starting the Multiplex

Click the Start button on the dashboard. DABcast will:

  1. Start one odr-audioenc + odr-padenc per enabled service
  2. Start odr-dabmux with the generated .mux config
  3. In HACKRF mode: wait 500ms, then start odr-dabmod and hackrf_transfer
  4. In EDI/HACKRF mode: expose a separate raw ETI monitoring stream for DABlin, even when PFT/FEC is enabled
  5. Activate the watchdog and metadata update loop

Mux Input Buffer Tags

While ON AIR, a second tag next to the status badge shows how odr-dabmux receives each service's audio. DABcast reads it every 5 seconds from the dabmux management port (read-only, no action is taken). Hover a tag for details; the full list is in the ? (About) dialog.

TagMeaningWhat to do
🟢 BUF OKAudio arrives regularly, no recent buffer incidentNothing
⚪ UNSTABLE (grey)Past glitches only — typically the buffer filling up right after Start. dabmux keeps this state for several minutes.Nothing
🟡 UNSTABLE ▲Underruns increased during the last minute: the buffer ran empty and listeners may hear dropoutsCheck the source stream, network and encoder of that service
🟡 SILENCEData arrives but the audio is (almost) silentCheck the source programme
🔴 NO DATANothing arrives from the encoderCheck the encoder and its logs

The Mux inputs card sums these tags; SILENCE and NO DATA inputs are added to the Alarms card.

Audio Watchdog & Failover

How it works

DABcast uses an audio-based watchdog to detect stream failures. Rather than simply checking HTTP connectivity, it starts a lightweight probe encoder (odr-audioenc -s 15) against the main stream URL. If the encoder crashes or detects silence within 15 seconds, the stream is considered failed.

Failover sequence

  1. Watchdog detects encoder crash on the main stream
  2. DABcast immediately switches to the backup stream URL
  3. The status badge changes to WARNING (orange)
  4. A probe encoder periodically tests the main stream in the background
  5. When audio is detected on the main stream, DABcast switches back automatically
  6. Status returns to RUNNING (green)
Note
The probe encoder runs once per mux to avoid excessive CPU usage, checking each service sequentially with a ~17-second interval per service.

Watchdog parameters

ParameterValueDescription
Watchdog interval5 secondsHow often the watchdog checks each service
Crash threshold1 crashNumber of crashes before switching to backup
Probe silence timeout15 secondsTime for audio probe to detect silence
Stable window30 secondsUptime needed to reset crash counter

Preset management

Complete multiplex configurations can be saved as presets (JSON files). Use File → Save Preset to export your configuration, and File → Load Preset to restore it. The active configuration is always stored as demo.json.

Service Management

  • Enable / Disable: toggle a service without removing its configuration
  • Logo upload: upload a JPEG image for SLS (slide show) broadcasting
  • Reorder services: drag services to change their order in the multiplex
  • Import / Export: copy individual service configurations between presets

Auto-start

Enable Auto-start on boot in Settings. DABcast will automatically restart the multiplex 2 seconds after the web server starts — ideal for unattended broadcast servers. The systemd service is configured to start on boot by default.

Troubleshooting

The web interface is not accessible

  • Check the service is running: sudo systemctl status dabcast
  • Verify port 9090 is not blocked by a firewall: sudo ufw allow 9090
  • Check logs: sudo journalctl -u dabcast -n 50

Encoder keeps crashing

  • Check that the stream URL is reachable from the server: curl -I <url>
  • For HTTPS streams, use GStreamer input mode (not VLC)
  • Ensure enough bandwidth — streams above 320 kbps may saturate slow connections
  • Check DABcast logs in Settings → Logs

No audio in the DAB+ signal

  • Verify odr-audioenc is listed as RUNNING in the process list
  • Check the ZMQ port is not used by another process: ss -tlnp | grep 930
  • Verify the bitrate and protection settings match your multiplex plan

A service shows UNSTABLE ▲ or NO DATA

  • The encoder may be running while its audio does not reach the multiplex in time: hover the tag to see how many underruns were added
  • Recurring UNSTABLE ▲: the source stream or network delivers irregularly — test the URL, or try a backup stream
  • NO DATA: check the encoder in Logs; it may be stuck or unable to reach its stream
  • "Stats unavailable" in the About dialog: the dabmux managementport is disabled (0) or not reachable on localhost

Metadata not updating

  • Ensure odr-padenc is running (shown in the process list)
  • For JSON API metadata, verify the API URL returns valid JSON
  • Check that the DLS text is not empty in the metadata source

Viewing application logs

# Live log output
sudo journalctl -u dabcast -f

# DABcast internal logs (Settings → Logs in the web UI)
sudo tail -f /var/lib/dabcast/logs/dabweb.log

Manual start (for debugging)

sudo -u dabcast env DABCAST_DATA_DIR=/var/lib/dabcast /opt/dabcast/bin/dabcast

Uninstallation

Remove DABcast (keep data)

sudo dpkg -r dabcast

Remove DABcast and all data

sudo dpkg --purge dabcast
sudo rm -rf /var/lib/dabcast

Remove ODR-mmbTools

Run the included uninstall-tools.sh script (available in the DABcast source repository).
