User Guide
DABcast
Open-source DAB+ Broadcast Management Software
Version 1.10.0 — November 2026
A web-based control interface for the complete ODR-mmbTools chain — audio encoding, metadata, multiplexing and RF output — from a single browser window, on any device.

Overview

DABcast is a Node.js web application that orchestrates the full ODR-mmbTools process chain to produce and broadcast a DAB+ digital radio multiplex. It is designed to run on a dedicated Linux server or a Raspberry Pi 4/5, and is accessed from any browser on the local network.

Open source — GNU AGPL v3
DABcast is free software: free to use (commercial broadcasters included), modify and redistribute. A modified version that is distributed or made available over a network must stay under the AGPL v3, with its source code. Source code: github.com/DABodr/DABcast-diffusion-software.

ODR Process Chain

DABcast manages the following ODR-mmbTools process chain:

odr-audioenc × N  ──ZMQ──► odr-dabmux ──EDI──► [odr-dabmod ──SoapySDR──► SDR]
odr-padenc × N   ──FIFO──► odr-audioenc          └──► EasyDAB, modulators, converters…

Each radio service (programme) runs its own odr-audioenc and odr-padenc instance. All audio streams are fed into a single odr-dabmux instance. With an SDR output, odr-dabmod generates the RF signal and drives the SDR itself through SoapySDR (a HackRF output saved by an earlier version still uses hackrf_transfer until it is saved again).

System Requirements

Hardware

  • PC / Server: any amd64 / x86-64 machine running Linux
  • Raspberry Pi: Raspberry Pi 4 or 5, 64-bit OS (arm64/aarch64)
  • Minimum 2 GB RAM recommended (4 GB for multi-service mux on Pi)
  • Stable internet connection for stream input sources

Software

  • OS: Debian 11/12 or Ubuntu 22.04/24.04 (or compatible)
  • ODR-mmbTools: odr-audioenc, odr-padenc, odr-dabmux (and odr-dabmod for RF output)
  • Optional: HackRF tools for RF transmission, ImageMagick for SLS slide processing
Important
The ODR-mmbTools must be installed before DABcast. Use the provided install-tools.sh script to install all required dependencies automatically.

Installation

Step 1 — Install ODR-mmbTools and dependencies

Run the provided script as root (or with sudo). It will install all required tools:

sudo bash install-tools.sh

The script installs: odr-audioenc, odr-padenc, odr-dabmux, odr-dabmod (optional), dablin and ffmpeg (web player), imagemagick (slides), and required libraries.

Step 2 — Install the DABcast package

On x86-64 / amd64 (PC, server)

sudo dpkg -i dabcast_1.10.0_amd64.deb

On Raspberry Pi (arm64)

sudo dpkg -i dabcast_1.10.0_arm64.deb

Step 3 — Enable and start the service

sudo systemctl enable --now dabcast

Step 4 — Access the web interface

Open a browser on any device on the same local network:

http://<server-ip>:9090

DABcast displays its own secure sign-in page. The default login is admin / dabcast. Change the password immediately on first login — the interface will prompt you to do so. You can keep a trusted device signed in, and use the ⚙ Settings button (top bar) to change the credentials or the web port, or to sign out.

Finding the server IP
Run hostname -I on the server to get its IP address. Example: http://192.168.1.50:9090

First Configuration

Multiplex Settings

Click Multiplex in the top bar to configure your multiplex:

  • Short label (PS8) / Label (PS16): the DAB+ ensemble name broadcast to receivers; the counters and a ⚠ hint show at once when the Label does not contain the characters of the Short label
  • Ensemble ID: 4 hex digits (e.g. F401); its first digit is the country code (with the ECC) — a ⚠ hint shows when it is 0 or differs from the first digit of the services' PI codes
  • Transmitter outputs: one or several transmitters, including an SDR on this server (DAB block / frequency, TX gain) — see Transmitter Outputs
  • ON AIR, a banner tells when a change needs a multiplex restart (applied on Save, after confirmation)

Adding a Service (Radio Programme)

Click + Add service (or double-click a row / Edit to change one). The dialog has three tabs:

TabFields
GeneralIdentity: PI (unique 4-digit hex, e.g. F9A3), PS8 (short name, 8 chars), PS16 (long name, 16 chars), language, PTY (genre). Live hints flag an invalid or duplicate PI and a PS8 whose letters are not in the PS16.
DAB coding: bitrate, codec (HE-AAC v1 / v2 / AAC-LC), protection EEP-A 1–4, sample rate, channels, PAD size. The capacity used by the whole multiplex (CU) is shown live.
Audio sourceInput mode: GStreamer (recommended, HTTPS), VLC, or ZMQ / EDI direct (an external encoder sends DAB+ audio). Main and backup stream URLs, each with a Test button (answer, format, current title), audio gain, and the failover settings.
MetadataWhere the titles come from (stream ICY, JSON API, manual text), the default text, DL+, the station logo and slides. See Metadata & slides.
Codec choice
At 96 kbps and below, HE-AAC v1 (SBR) usually sounds best. AAC-LC only pays off from about 128–144 kbps in stereo; below that it can sound metallic.

Starting the Multiplex

Click the Start button on the dashboard. DABcast will:

  1. Start one odr-audioenc + odr-padenc per enabled service
  2. Start odr-dabmux with the generated .mux config
  3. With an SDR output: wait 500 ms, then start odr-dabmod (it drives the SDR through SoapySDR; plus hackrf_transfer for a HackRF output saved by a former version)
  4. Always expose a separate raw ETI monitoring stream for the Player and DABlin, even when PFT/FEC is enabled
  5. Activate the watchdog and metadata update loop

Mux Input Buffer Tags

While ON AIR, a second tag next to the status badge shows how odr-dabmux receives each service's audio. DABcast reads it every 5 seconds from the dabmux management port (read-only, no action is taken). Hover a tag for details; the full list is in the Sys. info dialog.

TagMeaningWhat to do
🔵 STARTINGJust after Start: buffers are filling up and start-up underruns are normal. Ends on its own once the radio has had no new underrun for 5 seconds (usually about 15 s after Start, at most 1 minute). No warning or alarm is raised during this phase.Nothing
🟢 BUFFER OKAudio arrives regularly, no buffer incident in the last 30 seconds. Shown even while dabmux itself still reports Unstable for old glitches (e.g. the buffer filling up right after Start) — the tooltip says so.Nothing
🟡 UNSTABLE ▲Underruns increased during the last 30 seconds: the buffer ran empty and listeners may hear dropouts (▲ = increase since the previous reading)Check the source stream, network and encoder of that service
🟡 SILENCEData arrives but the audio is (almost) silentCheck the source programme
🔴 NO DATANothing arrives from the encoderCheck the encoder and its logs

The Mux inputs card sums these tags; SILENCE and NO DATA inputs are added to the Alarms card.

Transmitter Outputs

The Multiplex dialog lists the transmitter outputs: add one output per transmitter (EasyDAB V2, commercial modulator, converter, remote site, SDR plugged into this server). They all carry the same multiplex, at the same time.

Configurations made with a former version (TX mode EASYDAB, EDI or HackRF) are shown as the equivalent output when the dialog opens — same address, port and settings — and only saved that way when you press Save: an updated server keeps broadcasting exactly as before. A raw ETI copy (port 9901) is always kept for the Player and Dablin.

Outputs

Add one output per transmitter with the menu and + Add. All outputs carry exactly the same multiplex; each one has its own name and ON/OFF switch.

Connection state and supervision

While the multiplex is ON AIR, each output of the Multiplex dialog shows who is connected, refreshed every 5 seconds: "1 connected: 192.168.1.85" (green), "no transmitter connected" (orange), or "sending to …" for EDI/UDP (UDP has no connection: DABcast cannot tell whether the transmitter receives). A connected transmitter is not a proof that it is on air (its amplifier may be off), but a disconnection is seen at once.

  • SDR: every 5 s the watchdog reads the number of frames sent by odr-dabmod (its remote control, read-only) — an unplugged SDR leaves odr-dabmod running without any error. No frame for 15 s, or odr-dabmod stopped: one ERROR is logged, the output turns red (Device seems unplugged — NOT transmitting) and odr-dabmod alone is restarted every 30 s until it transmits again; the encoders, odr-dabmux and the other outputs stay on air. While another output is ON, the multiplex stays ON AIR; with the SDR as only output it shows FAIL.
  • ZMQ / EDI/TCP / ETI/TCP: when a transmitter that was connected has been gone for 15 s, an ERROR is logged (EasyDAB V2 disconnected…), and its return (connected again) as INFO. No alert for an output nobody connected to since the Start, nor around a Stop / Start.
  • These lines are in Logs › Watchdog (and odr-dabmod / SDR); the ERRORs are sent by Telegram, the returns too when Transmitter output back is ticked.

PFT / FEC and TIST offset

  • PFT / FEC (EDI outputs): splits each frame into packets and adds repair packets, so that the transmitter can rebuild what the network lost. Usual for EDI over UDP (FEC 2 is a good default); useless over TCP, which resends lost data itself. Not shown for EasyDAB.
  • TIST offset (EDI, and EasyDAB V2 when timestamps are sent): every frame carries the time at which it must be transmitted; the offset delays that time so that the transmitter can fill its buffer, and it keeps synchronised transmitters (SFN) aligned. Without timestamps, the EasyDAB V2 does not read it: the field is not shown and the offset is 0.

odr-dabmux has one value of each for the whole multiplex: the fields are shown in the blocks of the outputs that use them and stay in sync. A different delay per site is set on the site itself (transmitter or converter, below).

Distant transmitter or several sites: digris-edi-tcp-converter

Over the Internet or a long link, send EDI over TCP (reliable) to a small Linux machine next to the transmitter, which delivers it locally and buffers it. The digris-edi-zmq-bridge tools (GPL v3, developed for Opendigitalradio) do this.

  1. In DABcast: add an EDI/TCP output (e.g. port 13000) and set a TIST offset of at least 2 s. Open that port in the firewall / router for the site.
  2. On the site machine (Debian / Raspberry Pi OS), build the tools: 
    sudo apt install build-essential automake libtool libzmq3-dev git
git clone https://github.com/digris/digris-edi-zmq-bridge.git
cd digris-edi-zmq-bridge
./bootstrap.sh && ./configure && make && sudo make install
  3. Run the converter (both machines must have their clock synchronised by NTP / chrony): 
    # EDI/UDP to the local modulator 192.168.10.20, port 12000, FEC 2,
# each frame delivered 1 s before its timestamp
digris-edi-tcp-converter -c <dabcast-address>:13000 -w -1000 \
    -d 192.168.10.20 -p 12000 -f 2 -C "chronyc waitsync 2 0.01"

# or ZMQ for an EasyDAB on the site (it connects to this machine, port 18081)
digris-edi-tcp-converter -c <dabcast-address>:13000 -w -1000 -z *:18081

Several sites can each run a converter connected to the same EDI/TCP output (or each to its own output). Run the converter under a process supervisor (e.g. a systemd service) so that it restarts automatically.

Remote modulator with odr-dabmod

A machine with an SDR board on the site can run odr-dabmod fed by an EDI/TCP output of DABcast. Main settings of its configuration file:

[input]
transport=edi
source=tcp://<dabcast-address>:13000

[output]
output=soapysdr

[soapyoutput]
device=driver=hackrf
master_clock_rate=0   ; HackRF: no settable clock
channel=5A
txgain=40

Start from the complete example.ini of ODR-DabMod and validate the RF settings (gain, filter, channel) on the real hardware.

Radio transmission
Transmitting on a DAB frequency requires an authorisation from your national regulator. Test with a dummy load or within the limits of your licence.

Metadata & Slides

Each service sends a text (DLS), optional DL+ tags (artist / title) and pictures (SLS slides). Everything is set in the Metadata tab of the service dialog; the panel On air now on the right shows, live, the slide, the DLS and the DL+ tags really sent, with the reason of the last update.

Titles source

SourceUse
Stream (ICY)The title sent inside the audio stream (Icecast / Shoutcast). Nothing else to set.
JSON APIA now-playing address of the station (JSON, or a Server-Sent Events feed). Gives artist, title and usually the track cover.
Manual textA fixed text (the default DLS).

The green Validate button saves the metadata settings only, keeps the dialog open and restarts nothing (even ON AIR): the result appears in On air now within a few seconds.

Setting up a JSON API

  1. Paste the API address in JSON URL (the API, not the web page of the station).
  2. Click Detect keys: DABcast reads the JSON and fills Artist key, Title key and Cover URL key (the current item is preferred over history / next, the track cover over the station logo).
  3. Check with Test JSON and Test cover: green = received, red = nothing found.
  4. Validate (or OK).

Keys use dots for nested fields and numbers for lists (now_playing.song.title, data.0.artist); a|b means "b if a is empty".

End of a track
Many APIs keep returning the last song during ads. When the API gives the track duration (or start time / type), DABcast detects the end of the item and puts the station logo and the default text back on air until the next title — same rule for every station, no setting needed. Without such information, a song is capped at 8 minutes (setting End of item); shows and talk are never cut.

Slides

  • Any picture (logo or cover) is converted to a 320x240 JPEG; square pictures get side bands in the colours of their own edges (no black bands).
  • During a track cover, the logo is sent again every 40 s by default (During a cover, send the logo every … s, 0 = cover only).
  • Keep slides small: the PAD size sets the sending speed (shown under the PAD field). A 5–15 kB slide is sent in a few seconds.
  • Off air, the thumbnails of the services table show the logos only.

Web Player

Click Player in the top bar, choose a service and press play. The audio is decoded from the multiplex output itself (the same signal as the receivers), with left / right level meters, the DLS, the DL+ tags and the slides with their size. Two listeners at most. It requires dablin and ffmpeg on the server (installed by install-tools.sh).

Audio Levels

Click Levels (or the Mux inputs card) while ON AIR. DABcast measures the peaks of every service while this window is open and suggests a gain:

Setting / columnMeaning
Target typical peakWhere the usual peaks should be (−6 dBFS by default).
Analysis window5, 15 or 30 minutes. 15–30 minutes (songs, ads and jingles) gives a more reliable suggestion.
MaxHighest peak, in red above −3 dBFS: AAC encoding raises the decoded peaks by 1–3 dB, so higher peaks can crackle in receivers.
CLIP ×NThe encoder saturated N times: a cut of at least 2 dB is suggested.

Apply (or Apply all) saves the gain and restarts only that service's encoder (2–3 s gap on that service; the multiplex keeps running). An isolated peak does not make a quiet station quieter.

Audio Watchdog & Failover

How it works

DABcast uses an audio-based watchdog to detect stream failures. Rather than simply checking HTTP connectivity, it starts a lightweight probe encoder (odr-audioenc -s 15) against the main stream URL. If the encoder crashes or detects silence within 15 seconds, the stream is considered failed.

Failover sequence

  1. Watchdog detects encoder crash on the main stream
  2. DABcast immediately switches to the backup stream URL
  3. The status badge changes to WARNING (orange)
  4. A probe encoder periodically tests the main stream in the background
  5. When audio is detected on the main stream, DABcast switches back automatically
  6. Status returns to RUNNING (green)
Note
The probe encoder runs once per mux to avoid excessive CPU usage, checking each service sequentially with a ~17-second interval per service.

Watchdog parameters

Watchdog interval5 secondsHow often the watchdog checks each service

Preset management

The whole configuration (multiplex settings and services) can be saved and restored with the Import / Export menu: Export config / Import config (JSON), Export selected service / Import service (.dct with its logo), and Export all services (.zip), named all-services-<multiplex name>.zip. The active configuration is stored as /var/lib/dabcast/presets/demo.json.

Service Management

  • ON / OFF: an OFF service is left out of the multiplex (its capacity is freed) and keeps its configuration. ON AIR, switching it restarts the multiplex after a confirmation.
  • Logo upload: in the Metadata tab; any picture is converted to a 320x240 JPEG slide
  • Reorder services: drag the rows (in multiplex order, without filter) to change their order in the multiplex
  • Columns: status and mux buffer tag, PS8 / PS16, PI, PTY, bitrate, CU, protection, codec, channels, sample rate, input port, main / backup stream, level meters, DLS (cut with "…", full text on hover), DL+ and the slide on air
  • Import / Export: copy individual service configurations between servers

Auto-start

Tick Start multiplex at startup in the Multiplex dialog. DABcast will automatically restart the multiplex 2 seconds after the web server starts — ideal for unattended broadcast servers. The systemd service is configured to start on boot by default.

Settings (⚙)

The round ⚙ button of the top bar opens the Settings window:

  • Account: username and password (at least 10 characters, common passwords refused). Changing them signs out the other sessions.
  • Web server: the port of the web interface (9090 by default). Save & restart checks the port first (1024–65535, not used by the broadcast chain or by another program), asks for confirmation, then restarts DABcast; the page reopens at the new address. ON AIR, the restart cuts the multiplex for about 10 s (it comes back on air if Start multiplex at startup is ticked). A PORT= line in /etc/default/dabcast takes precedence and locks the field.

Telegram Notifications

The Telegram button forwards log lines to a Telegram bot (your phone, a group):

  1. Create a bot with @BotFather and copy its token; write to the bot (or add it to a group) and get the chat ID: open https://api.telegram.org/bot<token>/getUpdates and read chat.id (-100… for a group).
  2. Tick Enable Telegram notifications, enter the token and the chat ID, choose the minimum level (Errors only is recommended), then Send test and Save.
  • Errors sent include encoder crashes, failover, an SDR that stops transmitting and a transmitter that disconnects from its output — once per incident.
  • When the problem is over (off by default): Transmitter output back (SDR transmitting again, EasyDAB / modulator reconnected) and Service back on air (encoder running again for 30 s, back on its main stream) send a ✅ RESOLVED message, whatever the minimum level.
  • Send without notification sound delivers silently. The token is stored in /var/lib/dabcast/.telegram.json (readable by DABcast only) and is never shown again nor exported; a Telegram failure never affects the logs or the broadcast.

Logs

The Logs button shows the DABcast log, refreshed every 3 seconds. It opens on the latest lines and follows the new ones; scroll up to read, it stays there (back at the bottom: it follows again).

  • Tabs: All, odr-dabmux, odr-dabmod / SDR, odr-audioenc / odr-padenc, Metadata, Watchdog (crashes, failover, transmitter outputs), Running process (spawn / stop / exit), Errors.
  • Raw output (DEBUG) adds the console output of the ODR tools (e.g. the SoapySDR settings of odr-dabmod); the service menu keeps one service; Search filters the lines as you type (Esc clears it). ERROR lines are red, WARN yellow.
  • The window holds the last 1 MB of the file; Download (.log) gives the whole file. Clear Log empties it (after confirmation).

Troubleshooting

The web interface is not accessible

  • Check the service is running: sudo systemctl status dabcast
  • Verify the web port (9090 by default, see ⚙ Settings) is not blocked by a firewall: sudo ufw allow 9090
  • Port changed and forgotten: sudo grep -m1 '"port"' /var/lib/dabcast/settings.json
  • Check logs: sudo journalctl -u dabcast -n 50

Encoder keeps crashing

  • Check that the stream URL is reachable from the server: curl -I <url>
  • For HTTPS streams, use GStreamer input mode (not VLC)
  • Ensure enough bandwidth — streams above 320 kbps may saturate slow connections
  • Check DABcast logs with the Logs button

The SDR / HackRF does not transmit

  • Check device in its output: "No device found" = USB cable / port (lsusb) or missing SoapySDR module (SoapySDRUtil --info)
  • Red output Device seems unplugged: DABcast restarts odr-dabmod every 30 s; the transmission comes back by itself once the device is plugged in again
  • A HackRF that disconnects when it starts transmitting usually lacks power: plug it directly into the computer or into a powered hub, with a short cable
  • Look at Logs › odr-dabmod / SDR with Raw output ticked: the SoapySDR: Actual … lines show the frequency, rate and gain really applied

No audio in the DAB+ signal

  • Verify odr-audioenc is listed as RUNNING in the process list
  • Check the service input port (Port column) is not used by another process: ss -tlnp | grep 900
  • Verify the bitrate and protection settings match your multiplex plan

A service shows UNSTABLE ▲ or NO DATA

  • The encoder may be running while its audio does not reach the multiplex in time: hover the tag to see how many underruns were added
  • Recurring UNSTABLE ▲: the source stream or network delivers irregularly — test the URL, or try a backup stream
  • NO DATA: check the encoder in Logs; it may be stuck or unable to reach its stream
  • "Stats unavailable" in the Sys. info dialog: the dabmux managementport is disabled (0) or not reachable on localhost

Metadata not updating

  • Ensure odr-padenc is running (shown in the process list)
  • For JSON API metadata, verify the API URL returns valid JSON
  • Check that the DLS text is not empty in the metadata source
  • Use Test JSON / Detect keys, then look at On air now: its status line tells what was read and why the default text is shown (e.g. "item over" during ads)

Crackles in the audio

  • The source is probably too loud: open Levels, measure 15–30 minutes and apply the suggested gain (CLIP badge = the encoder saturates)
  • As a quick fix, lower the gain of that service by 2–3 dB (Edit › Audio source)

Forgotten password

sudo /opt/dabcast/bin/dabcast --reset-password
sudo systemctl restart dabcast

The password becomes dabcast (username kept) and a new one is required at the next sign-in. Add a username after --reset-password to change it too.
